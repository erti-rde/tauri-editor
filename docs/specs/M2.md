# M2 — Retrieval index

### M2-1 In-memory index

Refs: ADR-5 · Depends on: M1b-2

- AC-1 One index per open library, in Rust: L2-normalised `f32` rows over chunks, annotations
  and source notes, each entry tagged with `kind` and canonical id.
- AC-2 Built lazily on first query, off the async workers; rebuilt on a model change.
- AC-3 One query command returns one result type with `kind`; filters (project set, kinds)
  apply before scoring.
- AC-4 `search_sources` and `search_annotations` are served from it, and their existing tests
  pass unchanged.

### M2-2 Index stays consistent with the database

Refs: ADR-5 · Depends on: M2-1

- AC-1 Each writer updates the index: `store_chunks`, save and delete annotation, save and
  delete source note, alias changes, source removal.
- AC-2 A test per writer: after the write, the query results equal a full rebuild's.

### M2-3 Note-matching eval set

Refs: TEST · Depends on: M1b-8

- AC-1 ≥ 30 labelled pairs (paragraph → the note written about it) join `queries.json`.
- AC-2 `eval_retrieval` reports them separately, and `last-run.json` records them.
- AC-3 The existing easy and hard sets don't regress on Recall@1/5 or MRR.

### M2-4 Budget measured

Refs: ADR-5 · Depends on: M2-1

- AC-1 A synthetic library of 56k rows is generated reproducibly.
- AC-2 Measured and committed: single-paragraph query p50/p95 (target under 50 ms), build time
  (target under 2 s), resident memory.
- AC-3 If memory breaks the budget, int8 with an f32 re-rank of the top 200, measured the same
  way. Otherwise it's not built.

**M2 Verify:** the committed measurements; retrieval metrics unchanged or better.
